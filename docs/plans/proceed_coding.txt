│  30                                                                                           │
│  31 ### 2.1 Il Protocollo SBE (Simple Binary Encoding)                                        │
│  32 Non usiamo JSON o CSV in transito. Usiamo SBE.                                            │
│  33 *   **Perché:** Un tick JSON pesa ~150 byte e richiede parsing costoso (CPU). Un tick SBE │
│     pesa <50 byte e si mappa direttamente in memoria.                                         │
│  34 *   **Struttura del Pacchetto:**                                                          │
│  35     *   `Header`: BlockLength, TemplateID, SchemaID, Version.                             │
│  36     *   `Body`: SymbolID (int64), Timestamp (int64), Bid/Ask/Vol (int64 - prezzi          │
│     normalizzati per evitare float errors).                                                   │
│  37                                                                                           │
│  38 ### 2.2 Strategia Multi-Asset su MetaTrader 5                                             │
│  39 Per monitorare 10, 20 o 50 asset contemporaneamente senza crashare MT5:                   │
│  40 1.  **Market Watch Loop:** L'EA `Bridge.mq5` non deve essere attaccato a 50 grafici. Deve │
│     girare su **UN SOLO** grafico (es. EURUSD) ma usare `OnTimer` o `OnBookEvent` per iterare │
│     su una lista di simboli definiti nel "Market Watch".                                      │
│  41 2.  **Multiplexing:** Ogni pacchetto inviato al Gateway contiene un `SymbolID`.           │
│  42     *   Es. `1 = EURUSD`, `2 = BTCUSD`, `3 = GOLD`.                                       │
│  43     *   Il Gateway Go riceve il flusso misto e lo smista.                                 │
│  44                                                                                           │
│  45 ### 2.3 Storage: Dal "Data Lake" al "Feature Store"                                       │
│  46 L'archiviazione avviene in tre stadi (Medallion Architecture):                            │
│  47                                                                                           │
│  48 1.  **Bronze Layer (Raw Logs):**                                                          │
│  49     *   Il Gateway Go scrive file `.sbe` grezzi (append-only). È la "scatola nera" in     │
│     caso di disastri.                                                                         │
│  50     *   *Posizione:* `data/raw/`                                                          │
│  51                                                                                           │
│  52 2.  **Silver Layer (Structured Parquet):**                                                │
│  53     *   Ogni 15 minuti (o 100MB), il Gateway Go ruota il file e converte i dati in        │
│     **Apache Parquet**.                                                                       │
│  54     *   *Vantaggio:* Parquet è colonnare. Se la rete neurale serve solo il "Bid", legge   │
│     solo quella colonna, ignorando il resto. Compressione 10x rispetto al CSV.                │
│  55     *   *Schema:* `Timestamp, SymbolID, Bid, Ask, Volume, Flags`.                         │
│  56     *   *Posizione:* `data/parquet/`                                                      │
│  57                                                                                           │
│  58 3.  **Gold Layer (Feature Store - Python):**                                              │
│  59     *   Qui entra in gioco il modulo Python. Legge i Parquet e calcola le feature         │
│     complesse (RSI, Volatilità, FracDiff).                                                    │
│  60     *   Salva i tensori pronti per PyTorch/TensorFlow.                                    │

│  64 # 3. La Strategia di Machine Learning (Il "Cervello")                                     │
│  65                                                                                           │
│  66 Per addestrare la rete a determinare Entry, Take Profit (TP) e Stop Loss (SL) ottimali,   │
│     non usiamo la predizione del prezzo (che è rumore), ma la classificazione delle           │
│     probabilità.                                                                              │
│  67                                                                                           │
│  68 ### 3.1 Feature Engineering Avanzata                                                      │
│  69 Nel file `features.py` abbiamo implementato concetti istituzionali:                       │
│  70                                                                                           │
│  71 *   **Fractional Differencing (FracDiff):**                                               │
│  72     *   *Problema:* I prezzi non sono stazionari (la media cambia), ma se fai la          │
│     differenza (Prezzo oggi - Prezzo ieri) per renderli stazionari, cancelli la memoria del   │
│     trend.                                                                                    │
│  73     *   *Soluzione:* FracDiff differenzia solo "una frazione" (es. 0.4). Mantiene la      │
│     stazionarietà E la memoria storica. **Cruciale per le reti neurali.**                     │
│  74                                                                                           │
│  75 *   **Ortogonalizzazione (PCA):**                                                         │
│  76     *   Indicatori come RSI e MACD sono spesso correlati. Usiamo la PCA per pulire i dati │
│     e dare alla rete input non ridondanti.                                                    │
│  77                                                                                           │
│  78 ### 3.2 Il Metodo delle Tre Barriere (Triple Barrier Method)                              │
│  79 Come definiamo se un trade è "buono" per il training?                                     │
│  80 Non basta dire "il prezzo è salito".                                                      │
│  81 Ogni trade ha 3 limiti:                                                                   │
│  82 1.  **Barriera Superiore (TP):** Profitto desiderato (es. +2%).                           │
│  83 2.  **Barriera Inferiore (SL):** Perdita massima (es. -1%).                               │
│  84 3.  **Barriera Verticale (Tempo):** Tempo massimo di hold (es. 1 ora).                    │
│  85                                                                                           │
│  86 **Labeling:**                                                                             │
│  87 *   Se tocca TP per primo -> Label `1` (Buy).                                             │
│  88 *   Se tocca SL per primo -> Label `-1` (Sell/Avoid).                                     │
│  89 *   Se tocca Tempo -> Label `0` (Exit Flat).                                              │
│  90                                                                                           │
│  91 La rete neurale non impara "quanto varrà Bitcoin", impara **"Qual è la probabilità di     │
│     toccare la barriera superiore prima di quella inferiore?"**.                              │
